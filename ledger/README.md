# TPALedger — local server-attestation registry

`TPALedger` is a **global, namespaced hash registry** for short-lived attestations made by a trusted WebAuthn-verification backend. The namespace is `(issuer address, mandateHash)`, so the same opaque hash may safely exist for different issuers.

> This contract records a **trusted verifier's attestation only**. It does **not** verify a native WebAuthn/passkey signature, translate a passkey into EIP-712, prove account ownership beyond the backend's policy, prove assets, move or custody funds, execute transactions, or prove payment/settlement.

There is no deploy script, RPC URL, key handling, wallet integration, token interface, payable method, fallback, or broadcast path in this project. The test runner starts an in-memory Ganache EVM only; it never contacts Rootstock, Bitcoin, Ethereum, or another external chain.

## Security and lifecycle model

A server account granted `RECORDER_ROLE` is the trust boundary. It must complete WebAuthn verification and its own replay, origin, challenge, credential, and user-account checks **before** calling `recordMandate`.

- Only `RECORDER_ROLE` may record or consume.
- `issuer` and `mandateHash` must be nonzero.
- Records live for an absolute timestamp that is **strictly after** `block.timestamp` and no more than **300 seconds** ahead.
- `isValid` is true only for `Active` records where `block.timestamp < expiresAt`; expiry is invalid at equality.
- An `(issuer, mandateHash)` namespace is permanently single-write. It cannot be re-recorded after expiry, consumption, or revocation.
- Consumption atomically changes an active, unexpired record to `Consumed`, so it occurs exactly once.
- The issuer or an approved recorder may revoke an unconsumed record. Revocation remains available while paused for incident response.
- `PAUSER_ROLE` can pause record/consume and unpause after recovery. `DEFAULT_ADMIN_ROLE` manages recorder/pauser roles through OpenZeppelin `AccessControl`; protect it with an organizational multisig or equivalent process in a real deployment.
- `MandateStatusChanged` indexes `issuer`, `mandateHash`, and actor, and includes each stored status transition. `getMandate` also reports a time-aware `Expired` status without a write.

The contract deliberately uses OpenZeppelin Contracts `5.6.1` for `AccessControl` and `Pausable`; it contains no hand-rolled cryptography.

## Later backend adapter interface

The stable Solidity interface is [`contracts/ITPALedger.sol`](contracts/ITPALedger.sol). A verifier adapter needs only:

```solidity
interface ITPALedger {
    function recordMandate(address issuer, bytes32 mandateHash, uint64 expiresAt) external;
    function consume(address issuer, bytes32 mandateHash) external;
    function revoke(address issuer, bytes32 mandateHash) external;
    function isValid(address issuer, bytes32 mandateHash) external view returns (bool);
    function getMandate(address issuer, bytes32 mandateHash)
        external view returns (Status storedStatus, Status effectiveStatus, uint64 expiresAt);
}
```

`mandateHash` should be a collision-resistant opaque value generated by the backend from its verified request context. Do not reuse a hash for a second lifecycle in the same issuer namespace, because the contract intentionally rejects re-recording.

## Reproducible local setup

Prerequisite: Node `22.13.x` and pnpm `10.18.0` (the pinned toolchain target). Install without package lifecycle scripts:

```bash
cd ledger
pnpm install --ignore-scripts --frozen-lockfile
pnpm test:local
```

This directory is an intentionally independent pnpm project: its `.npmrc` sets `ignore-workspace=true`, and its local [`pnpm-workspace.yaml`](pnpm-workspace.yaml) is the nearest workspace boundary. The checked-in [`pnpm-lock.yaml`](pnpm-lock.yaml) therefore resolves this toolchain only, rather than the enclosing DingDong application. Do not run the audit from the parent repository.

`pnpm test:local` first invokes `scripts/compile.js`, which pins `solc` to `0.8.24` and reads [`solc.config.json`](solc.config.json). It compiles with `evmVersion: "paris"`, the Rootstock-compatible target shown in the linked Rootstock Hardhat guide. The ignored `build/TPALedger.json` is then deployed only to a fresh in-memory Ganache EVM for each test.

Useful commands:

```bash
pnpm run compile       # local solc-js only; output is ignored in build/
pnpm test              # compile plus isolated local EVM behavior tests
pnpm run audit:toolchain  # audit this standalone compiler/test toolchain only
```

## Test coverage

The test suite exercises constructor safety; compiler target pinning; recorder-only authorization and front-run/squatting denial; issuer/hash namespace isolation; valid recording and status events; zero values; past expiry; the exact 300-second boundary; overlong lifetime; duplicate records; expiry exactly at the cutoff; issuer/recorder revocation and unauthorized revocation; one-time consumption; expired consumption; pause behavior; revocation during a pause; and authorized recovery.

## Limitations and operational responsibilities

This is intentionally a minimal ledger, not an authorization engine. It cannot determine whether the backend correctly verified a passkey or whether its clocks, account binding, challenge policy, issuer selection, and recorder-key protection are sound. Block timestamps have normal chain-level variance, so the 300-second window is an upper bound from the recording block and applications should use shorter windows when possible. A production owner must conduct independent code review, threat modeling, monitoring, key/role rotation, and any chain-specific validation before considering any deployment. No live deployment has been performed or prepared here.

## Dependency audit note

The included `pnpm-lock.yaml` records exact resolved packages. The project declares **no production runtime dependencies**; all packages are local compiler/test tooling. The audited pins are OpenZeppelin Contracts `5.6.1`, ethers `6.17.0`, Ganache `7.9.2`, Mocha `12.0.3`, and solc `0.8.24`. The local workspace applies only two transitive overrides: `ws` `8.21.0` and `tmp` `0.2.7`. They remediate the prior `ws` paths through Ganache and ethers and the `tmp` path through solc without changing the compiler pin or adding deployment tooling.

From `ledger/`, `pnpm audit --ignore-workspace --json` and `pnpm run audit:toolchain` both completed with exit code `0` after the lock refresh: **0 critical, 0 high, 0 moderate, 0 low** advisories across the 73 packages reported by pnpm. This is a standalone result, not an audit of the enclosing DingDong workspace. `pnpm test:local` also completed with **20 passing** tests. On Node 22.13, Ganache may log that its optional native µWS binary is unavailable and fall back to its JavaScript implementation; that is a performance-only local-EVM warning, not an audit finding.

No deployment plugin or external RPC package is included.
